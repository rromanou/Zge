Zge 隐私、透明度和使用条款（大白话版）

最后更新：2026年11月17日。这页是用大白话写的，没绕弯子，没藏着掖着。看不懂的地方，宁可多看两遍，也别瞎猜。

一、先说重点（懒得看全文的，看这一段就行）

  • Zge 是个聊天网站。消息、图片、文件都在你自己的浏览器里加密，加密完了才发出去。服务器只管“送快递”，拆不开盒子。
  • 聊天用的钥匙，永远不会明文上服务器。服务器上只有加密过的东西，对方一收到，服务器上那份就删。
  • 注册不要邮箱、不要手机号，只要一个密码（20到40个字符）。系统会随机给你一个“+9位数字”的号码，这就是你的账号。
  • 密码忘了、号码忘了，没人能帮你找回来，作者也不行。丑话说在前头：这是故意的，不是漏洞。
  • 但是，别把话说满：服务器看不到内容，可它看得到“谁在跟谁聊、什么时候聊、大概多大”。这叫元数据，下面会讲得清清楚楚。
  • 没有任何广告、没有统计代码、没有第三方跟踪，页面也不加载任何外部脚本。
  • 这个网站没有经过第三方安全审计。别把它当成万能的保险箱，下面“局限”那一节一定要看。

三、账号是怎么回事


    

  • 你点“Create account”，输入密码，系统随机生成9位数字，前面加个加号，比如 +123456789。这就是你的号码，别人用它来找你聊。
    • 

  • 密码必须20到40个字符，而且不能全是重复的字符。为啥这么长？因为服务器上存着的是你密码的哈希值，要是密码太短，被人撞库一下就开了。
    • 

  • 底层用的是 Supabase 的登录系统。它需要一个“邮箱”字段，所以我们塞进去一个假的：你的号码@zge.local。这个地址不是真的，不会给你发任何邮件。
    • 

  • 登录的时候，你的密码会通过加密连接（HTTPS）发到 Supabase 去验证，服务器那边存的是哈希，不是明文。说白了：密码不是“端到端”的，它得过一下 Supabase。这点必须跟你讲清楚。
    • 

  • 没有“忘记密码”这个功能。没有邮箱，没有手机，没有客服能帮你重置。号码记不住就抄在本子上，密码丢了，账号就等于丢了。
    • 

  • 登录状态只放在内存里，不写进浏览器的硬盘。所以刷新页面、关掉标签页，就要重新登录。
    • 

  • 登录输错了会有等待时间，错得越多等得越久。服务器那边 Supabase 本身也有限流。
    • 




四、加密到底是怎么搞的（一步一步讲）


    

  • 第一步：你注册的时候，浏览器自己生成一对密钥（椭圆曲线 P-256）。公钥发给服务器，放在你的资料里，谁都能通过你的号码查到。私钥只留在你自己的设备里，不会发出去。
    • 

  • 第二步：你开一个新聊天的时候，你的浏览器随机生成一把32字节的“聊天钥匙”。这把钥匙是这个聊天专用的。
    • 

  • 第三步：你的浏览器用你的私钥加上对方的公钥，算出一把只有你们两个能算出来的“共享密钥”，拿它把聊天钥匙加密（AES-GCM），再把加密后的结果交给服务器转交。服务器手里只有一包看不懂的乱码。
    • 

  • 第四步：对方上线以后，取走这包乱码，在自己的设备里用自己的私钥解开，得到聊天钥匙，存进自己的本地保险箱。然后服务器上那份立刻删除。聊天钥匙从头到尾没有以明文形式上过服务器。
    • 

  • 第五步：之后每条消息、每个文件，都是用这把聊天钥匙加密（AES-GCM）以后才发出去。接收方取走、解密、存到本地，服务器上的那份就删了。
    • 

  • 加密的时候还把“谁发的、哪个聊天”这些信息绑进去了。服务器想把一条消息偷偷挪到别的聊天，或者冒充别人，解密就会直接失败。
    • 

  • 群聊也是同一套：创建者给每个成员各发一份加密过的聊天钥匙，所有人用同一把聊天钥匙。
    • 




五、服务器上到底存了啥（一条一条列给你）


    

  • 资料表：你的号码、你的公钥。就这些。
    • 

  • 聊天表：聊天的一个很长的随机编码，加上里面有哪些号码。这是整个聊天唯一长期保存的东西。
    • 

  • 钥匙中转表：加密过的聊天钥匙。对方一取走就删，没取走最多留30天。
    • 

  • 消息表：加密后的消息或文件分块、发送者号码、接收者号码、发送时间。对方一取走就删，没取走最多留30天。
    • 

  • 通知表：“清空聊天”“删除聊天”“删除某条消息”这类清理指令，让对方的设备上线后照着删。对方处理完就删。
    • 

  • Supabase 登录系统：那个假邮箱（号码@zge.local）、密码哈希，还有 Supabase 自己记的登录时间、IP 这类系统日志。这部分归 Supabase 管，我们没法左右他们记多久。
    • 

  • “30天”的清理不是定时任务，而是有人登录时顺手触发的。所以说是“最多大概30天”，不是精确到秒。
    • 




六、服务器看不到啥


    

  • 看不到消息内容，看不到图片和文件的内容，连文件名也看不到（文件名也在加密的消息里面）。
    • 

  • 看不到你的私钥，看不到聊天钥匙，看不到你的联系人备注名。
    • 

  • 密码明文不存，只存哈希。
    • 




七、服务器看得到啥（这块别装没有）


    

  • 谁和谁有聊天，群里有哪些号码，聊天是什么时候建的。
    • 

  • 谁在什么时候给谁发了东西。每条消息的发送时间服务器是知道的。
    • 

  • 东西大概有多大。文字消息会补到512字节的整数倍，所以看不出你发了几个字，但看得出是长是短；文件被切成256KB一块，每块一样大，所以能大概猜出文件有多大。
    • 

  • 一个号码存不存在。你输入一个号码，系统会告诉你“找得到”还是“找不到”，所以号码本身不是秘密，别人知道你的号码就能给你开聊天。
    • 

  • Supabase 和放网页的托管方，都能看到你的 IP 地址和访问时间，这是上网的基本规则，我们管不着。
    • 

  • 管数据库的人（也就是运营者）能在后台看到上面这些表，也能删账号，但没法解开消息内容。
    • 




八、你设备上存了啥


    

  • 聊天钥匙、你的私钥、已经信任的对方钥匙指纹、所有消息、联系人备注名，全都存在你浏览器的本地存储里，而且是加密存的。
    • 

  • 加密用的是一把随机的“保险箱钥匙”，这把钥匙又被你的密码锁着（用密码算出来的，算了60万轮，就是为了让别人猜密码变得很慢）。保险箱钥匙只放在内存里。
    • 

  • 图片、视频、文件放在浏览器的另一块存储（IndexedDB）里，同样是加密的。
    • 

  • 实话实说，有两样东西没加密：一是你上次登录的号码，用来帮你自动填号码；二是本地存储项的“名字”，里面带着你的号码和聊天编码。也就是说，有人能翻你的浏览器，能看出你有哪些聊天，但看不到内容。
    • 

  • 五分钟没动静，系统自动把你登出，保险箱也就跟着锁上了。切到别的标签页回来时，如果已经过了五分钟也一样。
    • 

  • 没有云备份，没有同步。清掉浏览器数据、换电脑、换浏览器，聊天记录就没了，而且找不回来。想留着，自己想办法。
    • 

  • 我们不用 Cookie，不用任何统计、广告、跟踪。
    • 




九、怎么确认对方是真的对方


    

  • 第一次见到某个号码的公钥时，系统默认信任它并记下指纹（先到先得）。这个设计有个软肋：如果服务器在你第一次查的时候就给了你一把假钥匙，你是发现不了的。
    • 

  • 所以，重要的聊天，请点聊天顶上的“#”按钮，会出来一串安全号码。你和对方用别的渠道（当面、打电话）对一对，两边一模一样才算数。
    • 

  • 以后要是对方的钥匙变了（比如对方重装了），系统会弹窗问你信不信新钥匙。别手滑点“确定”，先去核对安全号码。
    • 




十、删东西：到底能删到什么程度


    

  • 删除单条消息：在消息上点右键（手机上长按），会出来菜单。“只删我这边”只删你自己设备上的。“全部删除”（只有你自己发的消息才有）会向服务器发一条删除请求；对方下次上线时，服务器把请求交给对方，对方的设备把这条消息（包括它的文件）从本地删掉，然后服务器上的请求也就删了。如果对方还没上线、消息还没被取走，之后消息一到，也会被直接丢掉。
    • 

  • 清空聊天：你本地清空，对方上线后也清空。聊天本身还在，钥匙还在，可以接着聊。
    • 

  • 删除聊天：两个人的聊天，你删了，对方上线后也会被删，钥匙一起没。群聊里点删除等于退群：你的消息会从别人的设备上清掉，群里只剩一个人的话，群就解散。
    • 

  • 删除账号：你的账号、公钥、没被取走的消息和钥匙都会从服务器清掉，你参与的聊天按上面的规则处理。
    • 

  • 清缓存：只清这台设备上的消息和文件，钥匙留着。“抹除设备”：这台设备上的消息和钥匙全清，并登出。
    • 

  • 要说在前头：删除靠的是对方的程序“听话”去删。对方要是改过代码、截了屏、拍了照、复制了文字，或者备份了浏览器数据，我们是拦不住的。“全部删除”是一个请求，不是一道保证。
    • 




十一、群聊、文件、图片


    

  • 群聊最多21个人（你加另外20个）。群里每个人都能看到所有成员的号码。
    • 

  • 有人退群以后，聊天钥匙不会换。他之后拿不到服务器上发给群的新东西，因为那些东西是按人单独发的，但这套设计防不了“服务器本身有问题”的情况。
    • 

  • 文件最大10MB。图片会先在你的设备上缩小（长边最多1280像素）并重新压成 JPEG，这样图片里带的拍摄地点这类附加信息（EXIF）就没了。
    • 

  • GIF、视频和其他文件是原样发的，里面可能带着拍摄地点、设备型号、时间之类的元数据。发之前自己想清楚。
    • 

  • 只有图片和视频会直接在页面里显示。其他文件只给你一个下载按钮，下载下来打开之前先想想，别随便点来路不明的东西，打开以后出了事，是你自己的事。
    • 

  • 多个聊天可以跟同样的号码同时存在，想开几个开几个。
    • 

  • 联系人备注名只存在你自己的设备上，服务器和对方都看不到。你可以给号码起名字，也可以给整个聊天起个只有你看得到的标题。
    • 




十二、我们做了哪些防护


    

  • 页面有严格的内容安全策略（CSP）：不加载任何外部脚本、不允许内联注入、不让别人把它嵌进别的网页、只允许连你自己的 Supabase。
    • 

  • 所有显示出来的文字都当纯文本处理，别人发来一段代码，也只会显示成一段字，不会被执行。
    • 

  • 数据库每张表都开了行级权限：你只能读发给你的东西，只能以你自己的号码发东西，而且只能发给同一个聊天里的人。
    • 

  • 通讯录不公开：不能列出所有号码，只能按你输入的号码逐个查（一次最多20个）。
    • 

  • 限流：每分钟发送量有上限，每个人收件箱有上限，一小时内开聊天的数量有上限，防止有人刷屏刷爆。
    • 

  • 收到的数据一律先检查格式再用，长度、编号、编码对不上的直接丢掉。
    • 

  • 收到的聊天钥匙，必须是从聊天成员发来的，而且必须是正好32字节才收。
    • 

  • 本地保险箱、会话只放内存、五分钟自动锁、登录失败递增等待、对方钥匙变更提醒、安全号码，上面都讲过了。
    • 




十三、局限（说实话，这些我们解决不了）


    

  • 没有第三方审计。代码开源，不代表有人认真看过。你有能力的话，请自己看或者找人看。
    • 

  • 网页每次都是从服务器上现取的。理论上，管网页的人（运营者）或者黑进服务器的人，可以换一份有毒的网页，偷走你的钥匙。这是所有网页版加密聊天都躲不开的问题。想更放心，就自己下载源码、自己部署，并且核对代码有没有被改。
    • 

  • 你的设备要是中了木马、装了恶意浏览器插件、被人看着屏幕、有人盯着你敲键盘，加密再好也没用。
    • 

  • 没有“前向保密”：聊天钥匙是固定的，一旦某个聊天的钥匙泄露，这个聊天里所有的历史记录都会暴露。
    • 

  • 元数据（谁和谁、什么时候、多大）藏不住，上面已经说清楚了。
    • 

  • 没有拉黑功能。别人知道你的号码就能给你开聊天，你只能删掉那个聊天（删了对方那边也会删）。
    • 

  • 服务有可能宕机、有可能丢数据、有可能哪天不干了，别拿它当唯一的存档。
    • 




十四、使用条件（用 Zge 就等于同意下面这些）


    

  • 你得达到你所在的国家或地区法律规定的、可以使用这类服务的年龄。
    • 

  • 不准用 Zge 干违法的事：诈骗、勒索、恐吓、骚扰、跟踪、发儿童性剥削内容、教唆或策划暴力和恐怖活动、侵犯别人隐私、传播木马病毒，等等，一概不行。
    • 

  • 不准攻击这个服务：不准爆破别人的账号、不准刷接口、不准想办法绕过限流、不准尝试读别人的数据。
    • 

  • 你发的东西，后果你自己负责。我们看不到内容，没法事先审核，也不会假装能管。但如果发现有人滥用服务，运营者保留限制、封停或删除对应账号的权利。
    • 

  • 服务按“现状”提供，不保证一直能用、不保证不出错、不保证不丢数据，也不保证适合你的某个特殊用途。在法律允许的最大范围内，因使用或无法使用 Zge 造成的损失，作者和运营者不承担责任。
    • 

  • 这些条件以后可能会改。改了以后你还继续用，就当你同意新的版本。每次更新，上面的日期会跟着变。
    • 

  • 具体适用哪个地方的法律，由运营者部署时另行写明，这里不瞎编。
    • 




十五、你的数据、你说了算


    

  • 你随时可以删掉自己的账号，服务器上你的账号资料和没取走的东西会被清掉。
    • 

  • 你随时可以清缓存或抹除设备，本地的东西你自己说了算。
    • 

  • 我们不卖数据、不拿数据做广告、不做用户画像，因为我们压根拿不到内容。
    • 

  • 跟你有关的服务器数据，主要就是第五节列的那些。想知道更多，直接看源码和 schema.sql。
    • 

  • 联系运营者的方式，由运营者在部署的页面或说明里写明。
    • 




十六、最后一句


Zge 想做的事很简单：尽量少收你的东西，收到的也尽量看不懂，用完就删。它能帮你挡住大多数窥探，但它不是万能的。该核对的核对，该小心的小心，别拿它去干要命的事还指望它兜底。
